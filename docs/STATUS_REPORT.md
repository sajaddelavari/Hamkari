# گزارش وضعیت محصول هم‌ساخت

تاریخ گزارش: ۲۰۲۶-۰۷-۲۴

مخزن: [sajaddelavari/Hamkari](https://github.com/sajaddelavari/Hamkari)

وضعیت انتشار: آمادهٔ پایلوت روی سرور تک‌نمونه‌ای

## جمع‌بندی مدیریتی

بازطراحی «هم‌ساخت» از نمونهٔ تک‌پروژه‌ای گلخانه به یک پلتفرم چندپروژه‌ای
انجام شده است. نسخهٔ فعلی امکان مدیریت سبد پروژه‌ها، جذب مشارکت، مالکیت و
انتقال داخلی سهام، عملیات مالی، اهداف و حاکمیت پروژه را فراهم می‌کند.

پیاده‌سازی، migration داده‌های قبلی، تست‌های خودکار، ممیزی امنیتی و
اعتبارسنجی رابط کاربری تکمیل شده‌اند. سرویس محلی در زمان تهیهٔ این گزارش
فعال است، دیتابیس وضعیت سالم دارد و schema آن نسخهٔ ۱۱ است.

## قواعد کلیدی پیاده‌سازی‌شده

- پیشرفت مشارکت فقط از نیازهایی محاسبه می‌شود که پیشنهاد پذیرفته‌شده دارند؛
  دنبال‌کردن و علاقه اثری روی درصد پیشرفت ندارند.
- برای هر نیاز فقط یک پیشنهاد می‌تواند هم‌زمان پذیرفته شود.
- موجودی سهام از دفترکل رویدادها محاسبه می‌شود و مقدار قابل‌ویرایش مستقیمی
  برای آن وجود ندارد.
- ثبت مالی و دفتر سهام تغییرناپذیرند؛ اشتباه مالی با reversal اصلاح می‌شود.
- عملیات حساس صدور، عرضه، انتقال و ثبت مالی idempotent هستند.
- تاریخ انقضای عرضه بر اساس منطقهٔ زمانی `Asia/Tehran` محاسبه می‌شود.
- وضعیت مصوبه فقط در مسیر `draft → open → closed` حرکت می‌کند.
- هنگام رأی‌گیری باز، دفتر سهام و فهرست واجدان رأی قفل می‌شوند تا یک واحد سهم
  نتواند دوبار رأی بدهد.
- عضو فعال هیئت‌مدیرهٔ بدون سهام یک رأی پایه دارد؛ سایر افراد باید قدرت رأی
  مشتق‌شده از دفتر سهام داشته باشند.

## امنیت و حریم خصوصی

- session مدیر با کوکی `HttpOnly`، `SameSite` و انقضای ۱۲ساعته
- محافظت CSRF و کنترل Origin برای عملیات مدیریتی
- رمز مدیر به‌صورت hashشده در production
- rate limiting برای ورود، API عمومی و اتصال زنده
- اعتبارسنجی موبایل ایران، اندازهٔ payload و ورودی‌های عددی
- honeypot ضداسپم و جلوگیری از ارسال تکراری فرم
- ذخیرهٔ hash توکن‌های پیگیری و session
- CSP و هدرهای امنیتی
- جلوگیری از دسترسی و mutation بین پروژه‌ها
- عدم انتشار موبایل، ایمیل، متن پیشنهاد و اطلاعات خصوصی ذی‌نفعان
- قفل اتمیک و audit trail برای عملیات حساس

ممیزی نهایی هیچ مانع امنیتی با شدت بالا یا متوسط پیدا نکرده است.

## معماری و عملیات

- Node.js 24
- فرانت‌اند سبک Vanilla ES Modules بدون وابستگی runtime
- SQLite با WAL، `busy_timeout` و transaction
- migration مرحله‌ای تا schema نسخهٔ ۱۱
- لاگ JSON، health endpoint و graceful shutdown
- backup امن SQLite همراه با integrity check
- فشرده‌سازی Brotli و پشتیبانی ETag
- Docker با کاربر non-root، healthcheck و volume پایدار
- دادهٔ نمایشی چندحوزه‌ای فقط در development
- ایجاد پروژهٔ خالی و خصوصی در اولین اجرای production

جزئیات مدل دامنه در [PLATFORM_MODEL.md](PLATFORM_MODEL.md) و راهنمای اجرا در
[README.md](../README.md) قرار دارند.

## مرزهای نسخهٔ فعلی

این نسخه برای پایلوت یک مدیر و استقرار تک‌سرور طراحی شده است. موارد زیر
عمداً خارج از دامنهٔ نسخهٔ فعلی هستند:

- تسویه بانکی و پرداخت آنلاین
- احراز هویت حقوقی، KYC و ثبت رسمی انتقال سهام
- قرارداد و امضای دیجیتال
- نقش‌ها و دسترسی‌های چندسطحی سازمانی
- پیامک و ایمیل خودکار
- چت، آپلود اسناد و marketplace بین‌سازمانی

دفتر سهام فعلی یک دفتر ثبت و گردش داخلی است و جایگزین ثبت قانونی یا تسویه
بانکی نیست.

## اقدامات لازم پیش از انتشار عمومی

1. تعیین VPS، دامنه، TLS و reverse proxy
2. تنظیم `PUBLIC_ORIGIN`، `ADMIN_PASSWORD_HASH` و `SESSION_SECRET` production
3. اجرای build کانتینر و آزمون restart، backup و restore روی سرور مقصد
4. جایگزینی محتوای نمایشی با اطلاعات پروژه‌های واقعی
5. تعیین فرآیند حقوقی سهام، قرارداد، KYC و تسویه خارج از سامانه
6. تعریف سیاست نگهداری backup، مانیتورینگ و پاسخ‌گویی به رخداد

## نتیجه

نسخهٔ فعلی از نظر کد، داده، امنیت، رابط کاربری و تست برای اجرای پایلوت آماده
است. کار توسعهٔ توافق‌شده پایان یافته و مانع فنی شناخته‌شده‌ای با شدت بالا یا
متوسط باقی نمانده است. مرحلهٔ بعدی، آماده‌سازی محیط production و ورود داده‌های
واقعی کسب‌وکار است.
